#+TITLE: Seed rotation

* Seed rotation

Replace the fleet root, the BIP-85 32-byte hex that every host, user, and
service identity derives from, without locking any host out. The planned
rotation moves from index =1= of the current mnemonic to index =0= of a new
mnemonic recorded on new seed plates.

This is a routine rotation, not compromise response. During a rotation the next
root travels through the public repository encrypted to keys that the current
root can derive. If the current root may be compromised, follow
[[file:compromise-response.org][compromise response]] instead.

** How it works

=secrets/rotation/state.json= holds the fleet-wide phase. =nixos rotation=
changes it; nothing else should.

| Phase   | Hosts hold     | Hosts use | Generated ciphertext targets        |
|---------+----------------+-----------+-------------------------------------|
| idle    | current        | current   | current keys                        |
| prepare | current + next | current   | current keys, plus the next root    |
| switch  | current + next | next      | next keys                           |

- *prepare* encrypts the next root to the current master as
  =secrets/rotation/next/hex.age=, writes next public keys beside the canonical
  ones (=*.pub.next=), and rekeys. On activation each host decrypts the next
  root with its current host key, derives its next host key and the next user,
  Btrbk, and Beszel identities, checks them against the =.next= public keys,
  and trusts both generations of host and login keys.
- *switch* selects the next generation: the next root for machine IDs, password
  hashes, and derived service credentials; the next host key first; the next
  SSH, Btrbk, and Beszel identities; ciphertext encrypted to next keys. Hosts
  still hold and trust current keys, so hosts on either side of a deployment
  keep talking to each other.
- *finalize* derives the new master from the next root, re-encrypts every source
  secret to it, promotes the =.next= public keys, sets =derivationIndex=,
  removes the next artifacts, and rekeys. On activation each host promotes its
  prepared host key and deletes the =.next= files.
- *back* steps one phase back: =switch= to =prepare=, or =prepare= to =idle=
  (removing the next artifacts).

Each host reports readiness in =/run/identity-rotation/ready=, written by
=identity-rotation-ready.service= after it verifies the next host key pair. In
the switch phase the service also requires the booted generation to be the
current one and the next machine ID to be active. =nixos rotation switch= and
=nixos rotation finalize= read that file from every host over SSH and refuse
unless each reports the current phase. Pass =--skip HOST= for a host that is
deliberately offline.

Each command that changes the phase requires a clean Git tree, computes its
change in a temporary worktree, and stages it with one =git apply --index=. An
interrupted command leaves the tree unchanged; run =git worktree prune= and start
again.
Commands stage changes but do not commit or push.

While the phase is not =idle=, =nixos generate=, =nixos add=, =agenix import=, and
=agenix update-masterkeys= refuse to run. =agenix edit= and =agenix rekey= still
work.

** Before you start

- Record the new mnemonic on the new seed plates. Keep the old plates and the
  current master passphrase until the finalized generation runs on every host.
- Derive /Derive Seeds (BIP-85) > 32-bytes hex > Index Number 0/ from the new
  mnemonic twice, ideally on two devices, and confirm the results match. The
  software cannot tell which mnemonic produced the hex you enter.
- Rotate before provisioning Dot. Dot has never booted, so it holds no keys to
  rotate: skip it with =--skip dot= and provision it afterwards from the new
  root using [[file:dot.org][its runbook]]. Do not provision Dot during a rotation.
- Every other host must be reachable over SSH from the operator machine and
  deployable from it. Plan the rotation for one sitting; hosts upgrade
  themselves from GitHub =main= at 04:00, so push a phase only when you mean to
  deploy it.
- Start from an up-to-date, clean =main= in =nix develop=, with
  =nix flake check --no-build= passing.

** 1. Prepare

#+begin_src sh
nixos rotation prepare 0
#+end_src

Confirm the derivation path, then scan the QR code or type the hex twice. The
command refuses the current root. Review the staged diff: =state.json=,
=secrets/rotation/next/hex.age=, a =.pub.next= beside every host and user public
key, and regenerated ciphertext including one =hex-next= per host. Commit and
push.

Deploy every host except Dot, then check:

#+begin_src sh
nixos rotation status
#+end_src

Each host should report =ready=. A host that is not ready failed to derive or
verify its next keys; read =systemctl status identity-rotation-ready= and the
activation output on that host before going further.

** 2. Switch

#+begin_src sh
nixos rotation switch --skip dot
#+end_src

The command stops unless every host except Dot is ready. Review the staged
diff: =state.json= and ciphertext regenerated for next keys. Commit and push.

Deploy every host with =nixos-rebuild boot= and reboot it. A reboot proves the
host boots with the next machine ID and identities; =switch= without a reboot
leaves =identity-rotation-ready= failed with "Reboot into this generation".
Check that each host still accepts SSH, decrypts its secrets, and runs its
services, then:

#+begin_src sh
nixos rotation status
#+end_src

To undo, run =nixos rotation back=, commit, and deploy everywhere. Hosts return
to current selection without recreating keys. A second =back= cancels the
rotation entirely.

** 3. Finalize

#+begin_src sh
nixos rotation finalize --skip dot
#+end_src

The command stops unless every host except Dot is ready in the switch phase.
It asks for a passphrase for the new master identity, then stages:

- every source secret re-encrypted to the new master, and =secrets/hex.age= as
  the new root
- the new =secrets/id_age.pub= and the promoted host and user public keys
- =derivationIndex = 0;= in =flake.nix=
- removal of =secrets/rotation/next/= and every =.pub.next=
- =state.json= back to =idle=, and ciphertext for the new keys

It replaces the ignored =secrets/id_age.age= with the new master, keeps the old
one as =secrets/id_age.age.previous=, and leaves the new master unlocked.
Review the diff, commit, push, and deploy every host. Each host promotes its
prepared host key on activation.

After every host runs the finalized generation:

- rebuild or re-enter =nix develop= so the =nixos= and =agenix= wrappers carry
  =derivationIndex = 0=
- delete =secrets/id_age.age.previous= and run =agenix lock=
- retire the old seed plates and the old master passphrase

** Afterwards

Provision Dot from the new root with [[file:dot.org][its runbook]]. A host that
was skipped for any other reason never received the next keys and cannot
decrypt the finalized configuration; restore it like a new host, staging its
host key derived from the new root with =sshed send=.
