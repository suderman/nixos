#+TITLE: YouTube subscriptions for Jellyfin

* YouTube subscriptions for Jellyfin

Lux runs the pinned nixpkgs =ytdl-sub= package through the native
=services.ytdl-sub.instances.youtube= module. The local
[[file:../modules/nixos/default/options/ytdl-sub.nix][module]] adds shared download settings, persistence, and disk-backed temporary
storage. [[file:../hosts/lux/configuration.nix][Lux]] enables it. Subscriptions live in Jon's =~/profile/apps/ytdl-sub/subscriptions.org=,
tangled to =subscriptions.yaml= beside it and carried to Lux by Syncthing. They stay
out of Git and the Nix store. Downloads and Jellyfin use Lux's local media
pool. No other host runs the downloader.

** Storage

- Completed media goes to =/media/youtube/video/<show>/Season <upload year>/=.
  This reuses Lux's existing lowercase video directory; =/media/youtube/audio=
  remains separate and untouched.
  Lux's =/media= is its persistent pool storage, already snapshotted and backed up.
  Jellyfin reads those same files locally on Lux. No copying service is needed.
- Each show contains its upstream
  =.ytdl-sub-<subscription name>-download-archive.json=. Keep that file with
  the media. It prevents duplicate downloads and preserves episode numbering.
  Renaming a subscription changes its show directory and archive identity.
- =services.ytdl-sub.subscriptionsFile= names the runtime subscription list.
  Lux sets =/home/jon/profile/apps/ytdl-sub/subscriptions.yaml=; the default is
  =/var/lib/ytdl-sub/subscriptions.yaml=. Systemd copies it as root into the
  unit's credentials directory on each start (=LoadCredential=), so Jon's
  private home and file modes need no permission changes. Never import
  this file into Nix or copy it into the public repository.
- =/var/lib/ytdl-sub/youtube= is the native service's current directory and
  contains working-directory locks. =/var/lib/ytdl-sub= persists through Lux's
  existing =/mnt/main/storage= helper with owner =ytdl-sub:media=, mode =0750=.
- =/var/cache/ytdl-sub/<subscription name>= holds videos during downloads and
  post-processing. Systemd creates the cache directory on Lux's main Btrfs
  disk. It is not =/run= tmpfs, not backed up, and disappears on a root reset.
  Upstream removes each subscription's temporary directory after a run,
  including on errors. An interrupted transfer may need to restart.
- =/run/ytdl-sub/youtube= remains the native runtime directory, but does not
  hold video downloads.

=RequiresMountsFor=/media= orders the service after
Lux's local Btrfs pool mount. =ProtectSystem=strict= remains enabled; only
=/media/youtube/video= is added to the native writable paths. Systemd makes its
state, cache, and runtime directories writable. A missing mount or missing
video directory must fail the run rather than write into a local fallback
directory. No NFS client mount or transfer between hosts is needed.

** First subscription

These are commissioning steps for Jon, not actions performed by the change.

1. On Lux, check the existing video directory and its permissions:

   #+begin_src sh
   findmnt -T /media/youtube/video
   stat -c '%u:%g %a %n' /media/youtube/video
   id jellyfin
   #+end_src

   Check =media= is GID =901= and Jellyfin belongs to it. The video directory
   needs group write/traverse access for Lux's downloader. Setgid preserves
   the media group for new shows and seasons. Check existing ownership before
   changing permissions; do not recursively change the existing library.
   Lux's service uses =Group=media= and application/systemd umasks =002=/=0002=,
   so Jellyfin can traverse directories and read videos, artwork, and NFO files.

2. Deploy the runtime-file configuration once through the usual approved
   workflow. Evaluate and build the generated native unit beforehand:

   #+begin_src sh
   nix develop --command nix eval .#nixosConfigurations.lux.config.system.build.toplevel.outPath
   nix develop --command nix build --no-link '.#nixosConfigurations.lux.config.systemd.units."ytdl-sub-youtube.service".unit'
   #+end_src

   Evaluation/building does not activate the configuration. No deployment or
   activation was performed for this implementation.

3. After activation on Lux, check the real mounted storage and service access:

   #+begin_src sh
   stat /media/youtube/video
   findmnt -T /media/youtube/video
   sudo -u ytdl-sub -g media test -w /media/youtube/video
   systemctl cat ytdl-sub-youtube.service
   #+end_src

   Expect Lux's Btrfs pool storage, not its root disk. Check the displayed service has
   =ReadWritePaths=/media/youtube/video= and a mount dependency. Do not trigger a
   download until this passes.

4. Edit =~/profile/apps/ytdl-sub/subscriptions.org= in Emacs on any host and tangle it with
   =C-c C-v t=. Its YAML block has this structure:

   #+begin_src yaml
   YouTube:
     "Channel name": "https://www.youtube.com/@CHANNEL/videos"

     # A leading ~ allows per-show settings, such as a shorter window.
     "~Other channel":
       url: "https://www.youtube.com/@OTHER/videos"
       only_recent_date_range: "7days"

     # Playlist.
     "Playlist name": "https://www.youtube.com/playlist?list=PLAYLIST_ID"
   #+end_src

   The top-level =YouTube= key selects the public shared preset. Names become
   show names; the =~= is not part of the name. Omitting
   =only_recent_date_range= uses the last 30 days. Keep names stable after
   downloads begin.

   Check Syncthing delivered the tangled file to Lux:

   #+begin_src sh
   ssh lux cat profile/apps/ytdl-sub/subscriptions.yaml
   #+end_src

   Preview with the dry-run procedure below, then start a manual sync. No
   rebuild, deployment, or timer restart is needed after changing
   subscriptions. Each run reads the file again.

5. In Jellyfin on Lux, add a separate TV shows library named =YouTube= with
   folder =/media/youtube/video=. Prefer local NFO metadata and local artwork; disable
   internet series matching for this library to avoid unrelated TV matches.
   Leave existing libraries alone. Scan after the first completed sync and
   check season/year, episode dates, descriptions, thumbnails, and playback.

** Download policy

The shared preset inherits upstream =Jellyfin TV Show by Date= and
=Max 1080p=. Upstream owns the filenames, same-day episode indexes, download
archive, TV-show/episode NFO, MP4 tags, info JSON, episode thumbnails, and
available channel avatar/banner artwork. Some playlists do not supply show
artwork; missing source artwork is not synthesized.

Seasons are upload years. Episodes use upstream
=upload-month-day-reversed= numbering, so newer uploads get lower numbers and
Jellyfin lists them first: 21 October becomes =e07299=, 4 October =e08999=.
The last two digits order same-day uploads.

The format sorter favors H264 video and AAC audio. MP4 merging and metadata
writing copy streams rather than routinely encoding video. If H264/AAC is
unavailable, other codecs can be selected within the 1080p cap; Jellyfin client
support still determines whether playback needs transcoding.

SponsorBlock requests and removes only =sponsor= segments. Intros, outros,
self-promotion, and other categories are untouched. Upstream leaves
=force_key_frames=false=, so cuts do not force a video re-encode. Cuts may be
less exact at keyframes, and SponsorBlock coverage is not guaranteed.

Only uploads from the last 30 days qualify by default. This bounds download
history, not disk usage or the number of videos in a busy channel. Set
=only_recent_date_range= on a =~= subscription, such as ="7days"= or
="1years"=, to request a smaller window or a deliberate backfill. The shared
preset uses upstream =Only Recent Archive=, not =Only Recent=, so date
filtering does not delete existing files. No retention or
maximum-file deletion policy is configured. An outage longer than the window
needs an explicit backfill. Metadata inspection can traverse older playlist
entries because playlists need not be ordered by upload date.

Keep upstream throttle protection enabled. The pinned preset sleeps about
14-28 seconds between videos, 16-26 seconds between subscriptions, and adds
0.75 seconds per metadata request. Its low-resolution assertion can stop a run
when it suspects throttling. Public YouTube extraction can still fail because
of rate limits, bot checks, unavailable videos, or extractor changes.

** Operation

The native timer runs at 00:00, 06:00, 12:00, and 18:00 in Lux's local timezone.
It does not replay missed calendar runs. Valid empty subscriptions use
the application's normal =No subscriptions ran= path without contacting YouTube.
A zero-byte file, such as an empty tangled block, skips through
=ExecCondition=. A missing file fails the unit at start (status =243/CREDENTIALS=),
which usually means Syncthing or tangling went wrong. Malformed YAML fails the run. No real subscriptions are stored in this repository.

After commissioning, run these commands on Lux:

#+begin_src sh
systemctl list-unit-files 'ytdl-sub-*'
systemctl list-timers --all ytdl-sub-youtube.timer
systemctl status ytdl-sub-youtube.service ytdl-sub-youtube.timer
sudo systemctl start ytdl-sub-youtube.service
journalctl -u ytdl-sub-youtube.service --since '24 hours ago'
systemctl --failed
#+end_src

To pause automatic updates, stop the timer. Stopping a timer does not stop an
already-running download. Inspect the service before stopping it separately.

#+begin_src sh
sudo systemctl stop ytdl-sub-youtube.timer
sudo systemctl start ytdl-sub-youtube.timer
#+end_src

Edit subscriptions only in =~/profile/apps/ytdl-sub/subscriptions.org=, never the tangled YAML.
Tangling and Syncthing both replace the file whole, and a run copies it once at
start, so edits cannot be read half-written or disturb a running sync. Do not
edit generated public preset YAML in the Nix store.

*** Dry-run

=ytdl-sub --dry-run= fetches metadata and previews output paths without
writing media or changing output archives. It is not an offline validator:
it contacts YouTube and may create temporary files and working-directory locks.

Use =systemctl cat ytdl-sub-youtube.service= to obtain its exact =ExecStart=
command and generated public config path. Run that command as =ytdl-sub:media=
with =--dry-run= added before =sub=, current directory
=/var/lib/ytdl-sub/youtube=, and =/dev/stdin= in place of
=%d/subscriptions.yaml=. Feed the list from Jon's shell, which can read it:

#+begin_src sh
cd /var/lib/ytdl-sub/youtube
sudo -u ytdl-sub -g media <ytdl-sub> --config <config.yaml> --dry-run sub /dev/stdin \
  --match 'Show name' < ~/profile/apps/ytdl-sub/subscriptions.yaml
#+end_src

The application lock prevents overlapping runs that share this cache and
current directory. Drop =--match= to preview every show.

Never run the generated command as root or from an arbitrary current directory.
Do not use =--update-with-info-json= as a validation command; it can rewrite
existing files. Pure Nix evaluation checks structure, not application schema
or live extraction. An empty CLI run validates shared settings but does not
validate a real URL.

*** Renumbering existing downloads

A naming change such as the episode ordering applies only to new downloads.
=sub --update-with-info-json= (=-u=) reapplies current naming to existing
media from each video's saved =.info.json=. It downloads nothing, rewrites
NFOs and tags, then deletes the old paths. The module enables
=experimental.enable_update_with_info_json= for this. Date windows and
SponsorBlock cuts are yt-dlp filters and postprocessors, so this mode does not
apply them and nothing is dropped or cut again. Throttle protection still
sleeps 14-28 seconds per video.

Renamed files are new items to Jellyfin, so watched state and resume points on
those episodes reset.

1. Pause the timer and check nothing is running:

   #+begin_src sh
   sudo systemctl stop ytdl-sub-youtube.timer
   systemctl is-active ytdl-sub-youtube.service
   #+end_src

2. Take a Btrfs reflink copy. It shares extents, so it is instant and costs
   almost no space:

   #+begin_src sh
   sudo cp -a --reflink=always /media/youtube/video /media/youtube/video.before-renumber
   #+end_src

3. Deploy the naming change, then run the update the same way as the
   dry-run, first with =--dry-run= to read the transaction log, then without:

   #+begin_src sh
   cd /var/lib/ytdl-sub/youtube
   sudo -u ytdl-sub -g media <ytdl-sub> --config <config.yaml> --dry-run sub -u /dev/stdin \
     < ~/profile/apps/ytdl-sub/subscriptions.yaml
   sudo -u ytdl-sub -g media <ytdl-sub> --config <config.yaml> sub -u /dev/stdin \
     < ~/profile/apps/ytdl-sub/subscriptions.yaml
   #+end_src

   Each show should report equal additions and removals, such as =+36 -36=.

4. Check the files, scan the Jellyfin =YouTube= library, then restart the
   timer and remove the copy:

   #+begin_src sh
   find /media/youtube/video -name '*.mp4' | sort
   sudo systemctl start ytdl-sub-youtube.timer
   sudo rm -rf /media/youtube/video.before-renumber
   #+end_src

   To roll back instead, stop the timer, move =video= aside, move the copy back
   to =/media/youtube/video=, and redeploy the previous naming.

** Optional authentication

No cookies are configured. Start with public URLs; live public extraction was
not tested during implementation. Add cookies only if a selected subscription
needs them. Cookies do not guarantee access or remove all YouTube bot checks.

Use the repository's existing agenix mechanism. The decrypted cookie file must
be owned by =ytdl-sub=, mode =0400=, under its runtime secret path. Reference
=config.age.secrets.<name>.path= as
=services.ytdl-sub.instances.youtube.config.presets.YouTube.ytdl_options.cookiefile=.
That reference is a runtime path string, not cookie contents. Do not use
=builtins.readFile=, a Nix path literal to plaintext cookies, or an inline cookie
string. The native sandbox can read service-owned secrets outside protected
home directories; verify access after provisioning.

** Verification limits

Implementation checks included Lux and Kit evaluation, Lux-only enablement
across all host configurations, native YAML/unit builds, systemd syntax/calendar
checks, and the pinned application's schema. Disposable local fixtures exercised format selection, date filters,
NFO/tags/thumbnails/info JSON, two distinct same-day filenames, and archive
reload/skip behavior. Fixture media was generated locally; it was not downloaded
from YouTube. SponsorBlock options were checked, but no live SponsorBlock cut
was performed. The initial implementation's separately named user-unit probe
verified =ExecCondition= skips. Runtime-file probes tested missing/zero-byte
file conditions, channel/playlist schema, repeated file reads, empty CLI runs
and rejection of malformed YAML. They used disposable local paths, not Lux's
production file or service. The native unit was syntax-checked under a probe name.

Jon's post-deployment checks confirmed Lux's Btrfs pool and service-user
write/traverse access to =/media/youtube/video=, owned by =jon:media= with
mode =775=. No permission change was needed. The runtime-file change still
needs deployment and local provisioning. Production sandbox access, live
YouTube extraction, and Jellyfin scan/playback remain commissioning checks.
